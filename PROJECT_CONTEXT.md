# 🏛️ КОНТЕКСТ ПРОЄКТУ: АРМ «РОЗКЛАДИ ТА ДИСПЕТЧЕРИЗАЦІЯ»
## КП «ОДЕСМІСЬКЕЛЕКТРОТРАНС» (КП «ОМЕТ»)

> **Версія:** 2.5 (Enterprise CAD/AVL & Transit Scheduling System)  
> **Останнє оновлення:** Вересень 2026 р.  
> **Призначення:** Єдиний цифровий комплекс планування розкладів, диспетчеризації в реальному часі та моніторингу роботи міського пасажирського електротранспорту м. Одеси (трамваї, тролейбуси, аварійно-відновлювальні служби).

## 1. СТЕК ТЕХНОЛОГІЙ ТА АРХІТЕКТУРА

### Frontend
- **Ядро:** React 18 (TypeScript), Vite 6, TanStack Query v5.
- **Стилізація та теми:** Tailwind CSS v4, класи `@custom-variant dark`, дизайн-токени для двох режимів:
  - `omet-clean`: світла тема для денної аналітики та інженерів служби руху (фон `#F1F5F9`, картки `#FFFFFF`);
  - `night-dispatch`: темна контрастна тема для цілодобових диспетчерських пультів (фон `#070D19`, картки `#0F172A`).
- **Картографія та ГІС:** Leaflet GIS (`react-leaflet`), підтримка підложок Carto Positron, OSM, Voyager, Esri Satellite, Dark Dispatcher.
- **Візуалізація даних:** Recharts (BarChart, PieChart), D3.js для діаграми Марея та Ґантта.
- **Державний зв'язок (State Management):** Zustand (`useScheduleStore`, `useRouteStore`, `useTelemetryStore`, `useAlertStore`, `useSettingsStore`).
- **Реактивність:** WebSockets (`useWebSocket`) для живої телеметрії Wialon та EasyWay, опитування раз на 3–4 сек із захистом від розривів.

### Backend
- **Фреймворк:** FastAPI (Python 3.11+), Pydantic v2, Uvicorn.
- **База даних:** PostgreSQL (`omet_db`) + SQLAlchemy 2.0 / Alembic (з резервним локальним fallback на SQLite `omet.db`).
- **Кешування та черги:** Redis (порт 6379) для сесій та тимчасового буфера GPS-координат.
- **Інтеграція телеметрії:** Wialon IPS / EasyWay API протоколи, GTFS та GTFS-Realtime генератор.

## 2. РОЛЬОВА МОДЕЛЬ КОРИСТУВАЧІВ (RBAC)

| Роль | Головні задачі | Ключові екрани в АРМ |
| :--- | :--- | :--- |
| **Головний диспетчер / CAD-AVL оператор** | Контроль випуску, реакція на аварії, розвороти (Short-Turn), відтяжки (Pacing), ліквідація скупчень («паровозів») | `/dispatch/map`, `/dispatch/matrix`, `/dispatch/orders`, `/dispatch/marey` |
| **Інженер служби руху (Розкладник)** | Розрахунок інтервалів, побудова добових розкладів, формування оборотів, облік норм КЗпП (10 год зміни, обід 4-5 год) | `/planning/parameters`, `/planning/matrix`, `/planning/shifts`, `/planning/interline` |
| **Начальник депо / Змінний майстер** | Добова рознарядка, призначення водіїв і бортів, контроль резерву та технічної готовності | `/crew/assignment`, `/crew/roster`, `/dispatch/matrix` (режим «У депо») |
| **Водій електротранспорту** | Дотримання графіка за контрольними точками (КТ), прийом оперативних наказів диспетчера | `/crew/terminal` (PWA термінал у кабіні), `/crew/schedule-book` |
| **Директор / Начальник служби** | Стратегічний контроль KPI, регулярність (OTP), звітність для Департаменту транспорту | `/` (Executive Dashboard), `/analytics` (OTP Reports) |

     - Зведена інформація про закріплені депо, сезон (Літо/Зима), тип дня (Робочий/Вихідний), кількість нарядів (двозмінні, розривні, пікові).
     - Список нарядів із закріпленими водіями (табельний номер) та бортами рухомого складу.
     - Швидкі дії:
       - 🔍 Перегляд та редагування в Шаховій таблиці (`/planning/matrix?routeId=...`);
       - ✂️ Перехід до Конструктора змін & КПЗ (`/planning/shifts?routeId=...`);
       - 💾 Додати в базу шаблонів (`SaveScheduleTemplateModal.tsx` -> `POST /api/v1/schedules/{id}/save-as-template`);
       - 📦 Перенести в архів (`POST /api/v1/schedules/{id}/archive`);
       - 🗑️ Видалити наряд з бази даних.

3. **Вкладка 6 «Архів розкладів та нарядів» (`StaticDutiesArchiveView.tsx`):**
   - **Сценарій 1 (Планове введення в дію нової версії):**

     - Диспетчерська служба завчасно отримує системне сповіщення про планову зміну графіка (`STATIC_SCHEDULE_PLANNED_ACTIVATION`).
     - Модальне вікно підтвердження `ScheduleActivationModal.tsx` із вибором дати та часу набуття чинності.

     - Повністю вилучено кнопку GTFS Open Data (ZIP) із планувальних вкладок згідно з прямим розпорядженням замовника (GTFS-експорт залишається виключно в налаштуваннях мережі).

   - **Керування архівом:**

4. **Серверна підтримка та БД (FastAPI + SQLite `omet.db`):**
   - Створено таблицю `schedule_templates` та модель `ScheduleTemplate` для збереження тиражованих розкладів підприємства.
